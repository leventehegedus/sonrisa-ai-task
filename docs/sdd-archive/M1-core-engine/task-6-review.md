### Strengths
- Small and readable: one file per adapter, and the registry is two lines, which is what §10 asks for ("one file plus one registry line").
- The webhook allow-list holds up. Checked by running `configSchema` against look-alikes: `https://hooks.slack.com.evil.io/x`, `https://hooks.slack.com@evil.io/x`, `HTTPS://HOOKS.SLACK.COM/x` and `https://hooks.slack.com:444/x` are all rejected. The required prefix ends in `/`, which closes the authority section, so any string that passes has the parsed host `hooks.slack.com`. `fetch` receives the same raw string, so the parse cannot diverge. Uppercase is a false negative, which is the safe direction.
- On the slack error path the thrown message is a fixed `Slack responded <status>`. The dry-run log contains only the message text, never `config.webhookUrl` (`slack.ts:124`). I tested a real Node fetch network failure: `e.message` is `fetch failed` and `e.cause` is `getaddrinfo ENOTFOUND <host>`. That is the host only, without the secret path.
- The `buildMessage` tests cover all three reason branches with exact strings, and `scrubSecrets` is tested for multiple occurrences, short values and non-object config.

### Issues
#### Critical (Must Fix)
None.

#### Important (Should Fix)
1. **Outbox filename collision silently overwrites messages.** `email.ts:46` writes `${Date.now()}-${safeTo}.json` with `writeFileSync`, which overwrites by default. Two alerts to the same recipient in the same millisecond produce the same path, and the dispatcher (Task 7) loops over pending deliveries back to back, where jsonTransport sends take well under 1 ms. The first message is lost while its delivery is still marked `sent`. Fix: add a uniqueness suffix (e.g. `${Date.now()}-${randomUUID().slice(0,8)}-${safeTo}.json`, or the message id from `info.messageId`), and/or write with `{ flag: 'wx' }`. Add a test that sends twice in a row and expects 2 files.
2. **The filename-hostile tests never exercise the sanitizer (named risk 4).** Both tests pass with `safeTo = config.to` (no sanitizing):
   - `channels.test.ts:166-174`: zod 4 `z.email()` rejects `a/../b@x.io` (verified: `success === false`), so `send` is never called. The outbox is never created, the `for` loop runs zero times, and the last assertion is trivially true. Even if the schema accepted the address, `path.join(outbox, '123-a/../b@x.io.json')` normalizes to `outbox/b@x.io.json` (verified). That stays inside the outbox and has no `/` in the name, so the test would still pass unsanitized. It asserts nothing in either branch.
   - `channels.test.ts:175-179`: `path.join(outbox, '123-../../evil.json')` resolves to `outbox/evil.json` (verified), because `123-..` is an ordinary segment that the first `..` pops. So the unsanitized path also stays in the outbox and the test passes without the sanitizer.
   - Fix: assert on the exact sanitized name. For example, send `{ to: '../../../x/evil' }` and expect `readdirSync(outbox)` to match `/^\d+-\.\._\.\._\.\._x_evil\.json$/`, and expect `readdirSync(dir)` to equal `['outbox']`. With three `..` segments the unsanitized write really does escape. For the schema branch, assert directly that `safeParse({to:'a/../b@x.io'}).success === false` rather than accepting either outcome.

#### Minor (Nice to Have)
1. **The adapter relies on the platform for network-error hygiene** (`slack.ts:125-129`). The default Node fetch does not leak the path (verified), but an injected `fetchImpl` or a future undici message might, and the adapter forwards `fetch` rejections raw, including `cause`. Wrapping the call is cheap and would let the adapter keep its own guarantee instead of depending on Task 7's scrub: `try { res = await f(...) } catch (e) { throw new Error(\`Slack request failed: ${(e as Error)?.name}\`) }`. Add a test with a `fetchImpl` that rejects with an error message containing the URL.
2. **The fetch has no timeout** (`slack.ts:125`). A slow webhook blocks that delivery until undici's default timeouts (minutes). Consider `signal: AbortSignal.timeout(10_000)`, or add a `// shortcut:` comment.
3. **Spec §10 asks the email outbox mode to log the message as well.** Pass `log` to `emailAdapter` and log a line with the subject and the file path (`index.ts:81`, `email.ts:43-47`).
4. **Long addresses can exceed the filename limit.** `z.email()` accepts a 64-char local part plus a domain of about 190 chars (verified accepted), so the filename `<13>-<to>.json` can go past 255 bytes. `writeFileSync` then throws `ENAMETOOLONG`, and that delivery fails permanently. Truncate `safeTo` (e.g. `.slice(0, 100)`).
5. **No regression test for look-alike webhook hosts.** The code is sound, but locking it in costs two lines: add `https://hooks.slack.com.evil.io/x` and `https://hooks.slack.com@evil.io/x` to `channels.test.ts:213-218`.
6. **A new transport is created on every send** (`email.ts:36`). This is harmless with jsonTransport and non-pooled SMTP, but it could be built once in `emailAdapter`.
7. **`String(info.message)`** (`email.ts:46`): with jsonTransport, `info.message` is already a JSON string, so `String()` is only a type cast. That is fine, but `info.message as string` would state the intent.
